## 为什么是现在

做 AI 短剧这件事，2025 年还是"手工作坊"，2026 年已经可以谈"流水线"了。三个变化凑齐了：

1. **视频模型能商用级出片了。** 主流阵营里，可灵 3.0 靠多主体参考和音画同出大幅简化了从分镜到成片的流程；Google 的 Veo 3.1 原生音频质量最好；Sora 2 电影感强；字节系的 Seedance（1.5 Pro / 2.0）在多模态输入和统一音视频架构上被不少测评列为当前最能打的一档。
2. **提示词封装有了统一标准。** Anthropic 在 2025 年 12 月把 Agent Skills 规范开放出来，一个 `SKILL.md` 文件——YAML 头部写 name 和 description，正文写触发条件、工作流程、输出格式、约束——已经被 30 多个智能体产品采纳。这意味着我写一次"短剧生产说明书"，Claude Code、Codex、各类国产智能体都能按它执行。
3. **编排工具直接给了现成积木。** n8n 官方模板库里已经有"Sora 2 + Veo 3.1 并行生成视频""Veo3 出片自动发 YouTube"这类工作流；Dify、Coze 也支持把 LLM 节点和 API 节点拖成一条线。

产业端也在验证这条路：中文在线的"AI 短剧工厂"宣称单分钟制作成本比传统 3D 动画下降超过 75%，11 月刚开源的 AniShort 影视工作台更是直接把"故事描述 → 任务分解 → 世界观/分集剧本/画面生成/精剪交付"做成了并行子任务。既然大厂都在这么玩，个人创作者没理由不给自己搭一条。

## 整体蓝图

我的设计目标很朴素：**输入就是一段话，其余全部自动，人只保留两道闸门——审大纲、审成片。**

```
一段话（灵感/梗概）
   ↓ ①大纲 Agent：扩成剧集大纲 + 分集钩子
   ↓ ②剧本 Agent：逐集分镜脚本（结构化 JSON）
   ↓ ③Skill 封装：把 ①②的方法固化成 SKILL.md，一次编写长期复用
   ↓ ④生成编排：n8n 并行调视频模型 API，按分镜批量出片
   ↓ ⑤聚合剪辑：剪映自动排序 + 配音配乐
   ↓ 人工审核后发布多平台
```

下面按五个阶段拆开讲。

## 阶段一：一段话是唯一的"人类输入"

不要小看这段话。流水线的质量上限由它决定，所以我给它定了个最小骨架：**题材 + 主角设定 + 核心冲突 + 爽点类型**，例如：

> "女频穿越漫剧：现代农科院研究员穿成流放边关的罪妻，靠育种技术开荒养崽，前夫一家追悔莫及。每集结尾留一个钩子，共 20 集。"

这句话直接进系统，不做任何手工润色。选题判断（比如目前女频种田穿越、男频玄幻系统仍是流量大盘）交给大纲 Agent 去做，人只负责给方向。

## 阶段二：大纲脚本——让推理模型干"编剧总监"的活

用带推理能力的模型（DeepSeek、Kimi、Claude 一类）做第一段处理，关键不是"写得好看"，而是**输出必须结构化**。我的提示词要求它一次性吐出三层 JSON：

- **世界观层**：时代背景、金手指规则、场景清单（后续所有镜头的"场景宪法"）；
- **分集层**：每集一句话梗概 + 开场 3 秒钩子 + 结尾悬念，短剧的命根子是钩子，这一步强制它每集检查；
- **角色层**：每个角色的定妆描述（发型、服饰、体态、标志性细节），这是后面保持"角色不崩脸"的锚点。

大纲生成完，**第一道人工闸门**：5 分钟扫一遍分集钩子，不顺的直接回炉，这一步千万别省——错误的大纲会被下游放大成 20 集废片。

## 阶段三：分镜脚本——把"文学"翻译成"指令"

剧本 Agent 按集消费大纲，产出逐镜表。每个镜头一条记录，字段固定：

```json
{
  "shot": 3,
  "duration": "5s",
  "scene": "边关茅屋·夜",
  "camera": "近景/轻推",
  "visual_prompt": "女主借着油灯翻看育种笔记，手边婴儿熟睡，冷色调，烛光在镜片上反光",
  "dialogue": "这批粟种……至少能活过两个冬天。",
  "character_refs": ["女主v2", "婴儿v1"]
}
```

`visual_prompt` 是按目标模型的口味生成的——同一个镜头，给可灵和给 Veo 的提示词写法不一样，所以脚本里同时存"通用描述"和"模型适配描述"。这一步纯靠 LLM，模板化提示词即可，不需要人参与。

## 阶段四：封装成 Skill Prompt——一次编写，天天自动

前面三段提示词如果每次对话都手贴，就还是"手工"。2026 年的正确姿势是把它们做成 Agent Skill，目录结构就是规范里的那套：

```
duanju-factory/
├── SKILL.md          # 核心：触发条件 + 流程 + 输出格式 + 约束
├── references/       # 钩子写法手册、各视频模型的提示词口味表
├── assets/           # JSON schema、分镜表模板
└── scripts/          # 提交生成任务、轮询取片的脚本
```

SKILL.md 骨架长这样：

```yaml
---
name: duanju-factory
description: 将一段话故事灵感扩展为短剧大纲、分镜脚本并调用视频模型批量出片。当用户输入剧集灵感并要求生成短剧时使用。
---

## 工作流程
1. 校验输入包含题材/主角/冲突/爽点四要素，缺失则追问一次
2. 按 references/hook-playbook.md 生成三层 JSON 大纲，等待用户确认
3. 逐集生成分镜表（assets/shotlist.schema.json 校验字段）
4. 对每个镜头按目标模型口味表改写 visual_prompt，绑定角色参考图
5. 调 scripts/submit_jobs.py 并行提交生成任务，轮询回收
6. 产出 manifest.csv（镜头→成片路径映射），交剪辑环节

## 约束
- 角色描述必须引用角色层定妆原文，禁止自由发挥外貌
- 单镜头生成失败重试不超过 2 次，超出记入待人工清单
```

两个经验：`description` 用第三人称写清"什么时候触发"，命中率完全靠它；**复杂脏活放 scripts/，SKILL.md 只做调度**——把"提交任务、轮询、重试"写成脚本，让模型只负责按说明书调用，稳定性比让模型现场写代码高一个量级。

## 阶段五：批量生成与编排——这才是"自动化"本体

出片环节我有两条路线，按预算选：

**路线 A：一站式工作台（省时省心）。** 即梦 11 月刚上线的"短剧工作室"把剧本、角色设定、智能分镜、视频生成收进同一条流程，角色绑定后跨集不换脸；PixTV（9 月上线）用"无限画布 + 多模型工作台"把原来四五个软件来回搬素材的活收进一张画布；SeaVideo 这类平台则集成了 Seedance、Veo、Kling 多模型。适合快速起量，缺点是批次多了不好做并行调度。

**路线 B：API + n8n 编排（真正的流水线）。** 分镜表落库（Google Sheets / Airtable / 数据库都行），n8n 用 Loop 节点逐镜分发：

1. **并行出片**：参照官方模板"Sora 2 + Veo 3.1 via parallel processing"的思路，重要镜头双模型各出一条，抽卡择优；量大且求性价比的镜头走可灵 API；
2. **异步轮询**：视频生成动辄几分钟，节点设 Wait + 轮询，取回 MP4 落对象存储；
3. **失败自动重试 2 次**，仍失败进人工清单——这条规则直接来自 SKILL.md 的约束，保证编排层和技能层口径一致。

一部 20 集 × 每集 40 镜的剧，约 800 个镜头，按 5 路并发跑，出片环节一整晚能完成。最后一道人工闸门放在聚合处：剪映专业版的 AI 镜头排序按分镜表自动排列素材，配字幕、口型对齐、BGM，人只翻检崩脸和穿帮的镜头。

## 三个坑，先打预防针

- **角色一致性是最大成本。** 一定让"角色层定妆描述 + 参考图绑定"贯穿全流程，任何环节模型都不许即兴改外貌；
- **别追求 100% 无人化。** 大纲、成片两道闸门是 ROI 最高的两处人工投入，中间环节才是自动化该吃掉的；
- **合规披露。** 各平台对 AIGC 内容有强制标注要求，发布环节把声明做成流水线固定字段，别靠记忆。

## 结尾

这套东西最妙的一点是：**它的起点真的只是一段话。** 剩下的五段流程，2026 年的工具链已经全部给齐——模型负责创意和翻译，Skill 负责固化方法，编排负责批量和重试，人只站在闸门边上。接下来要拼的，是谁的钩子更好看。
